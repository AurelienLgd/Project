# Security policy

## Reporting a vulnerability

Please do **not** open a public issue for security problems.
Use GitHub's private vulnerability reporting instead:
**Security** tab → **Report a vulnerability**.
You will get an answer within 7 days.

## Secrets: rules for everyone working on this repository

This repository is public. Anything pushed, on any branch, even for a few
seconds, must be considered leaked.

1. **No secret in Git, ever.** Passwords, tokens, API keys, private keys,
   Ansible Vault passwords, Terraform state and `*.tfvars` stay out of the
   repository. `.gitignore` already excludes the usual files.
2. **Where secrets live instead:**

   | Context | Storage |
   | --- | --- |
   | Local lab | `lab/.env`, generated by `./scripts/generate-lab-env.sh` (gitignored, mode 600) |
   | Ansible | `ansible-vault` encrypted files; the vault password stays on your machine or in a password manager |
   | Terraform | Environment variables or a gitignored `terraform.tfvars`; remote state in an encrypted backend |
   | CI | GitHub Actions secrets, scoped to an environment when possible |

3. **Commit only templates** such as `.env.example` or `*.tfvars.example`,
   with `change-me` placeholders.
4. **Guard rails:** the `pre-commit` hooks (gitleaks, detect-private-key) block
   most mistakes before the commit is created, and the `security` workflow
   scans the full history of every branch on each push.
5. **Synthetic data only.** No production or customer data, logs, exports
   or screenshots, even "just for a test".

## If a secret was committed

1. **Rotate it first.** Change the password or revoke the token immediately.
   Removing the commit is not enough: forks, clones and caches keep it.
2. Tell the repository owner.
3. Only then clean the history (`git filter-repo`), force-push with the
   owner's agreement, and ask every collaborator to re-clone.

## Supported versions

Only the `main` branch receives security fixes.
